# RND — Secure Downloads Module
**Plugin:** purecart  
**Module:** Secure Downloads  
**Phase:** 1 (signed tokens, streaming, license gate) · Phase 2 (cloud storage, video protect, media library guard) · Phase 3 (geo-blocking, CDN signed URLs, DRM)  
**Standalone:** Yes — works without Licensing or Updates modules  
**Depends on (optional):** `RND-licensing.md` — when License module is active, downloads are license-gated

---

## Overview

WooCommerce's built-in downloadable file system exposes direct file URLs after purchase. These URLs can be shared, scraped, or bookmarked indefinitely. PureCart's Secure Downloads module replaces WooCommerce's download links with signed, expiring, count-limited tokens that are validated server-side on every access. Files are delivered through PHP (or a cloud redirect) — the actual file path is never exposed to the customer.

### What Makes It Different from WooCommerce Native

| Capability | WC Native | PureCart |
|---|---|---|
| Signed expiring URL | Partial (nonce, email in URL) | HMAC-SHA256, configurable TTL |
| License-gated downloads | No | Yes — checks active license before serving |
| Download count enforcement | WC global setting | Per-order, per-file, filterable |
| IP logging per download event | No | Yes, every event |
| Geo-blocking | No | Phase 3 (ip-api / MaxMind) |
| File path exposed to browser | Yes (if WC redirect mode) | Never |
| Cloud storage (S3 / R2) | No | Yes (Phase 2) |
| Video streaming protect | No | Yes (Phase 2) |
| Non-WP digital products | No | Yes — all file types |
| X-Sendfile / X-Accel-Redirect | No | Yes |

### Problem It Solves

- WooCommerce download URLs contain the file key and order key in the query string — shareable and bookmarkable
- WooCommerce has no concept of license-gated file access
- WooCommerce only handles WordPress-hosted files — no S3, no R2, no CDN
- EDD handles download logging but only for EDD products, and has no license gate on downloads
- No existing WooCommerce plugin covers all digital product types: plugins, software, ebooks, videos, audio, fonts, templates, 3D models, source code archives, etc.

## Token Flow

```
Order Completed → woocommerce_order_status_completed
    │
    └── OrderHandler::on_order_completed( $order_id )
            └── For each downloadable item in order:
                    └── TokenManager::create_for_order_item( $order_id, $item_id, $file_id )
                            ├── Reads _purecart_download_limit    (per-product meta, default: 0 = unlimited)
                            ├── Reads _purecart_download_expiry_days (per-product meta, default: 0 = never)
                            ├── Generates 64-char hex token: bin2hex( random_bytes(32) )
                            ├── INSERTs row in wp_purecart_downloads
                            └── Returns token string

woocommerce_downloadable_file_download_url filter
    └── DownloadDispatcher::secure_download_url()
            └── Returns: home_url('/purecart-download/{token}')

Customer clicks download link → /purecart-download/{token}
    │
    └── DownloadDispatcher::handle()
            ├── TokenManager::validate( $token )
            │       ├── SELECT row WHERE token = ? AND expires_at > NOW() (or expires_at IS NULL)
            │       ├── Check: max_downloads == 0 OR download_count < max_downloads
            │       └── [Optional, if Licensing active] LicenseValidator::check_active( $license_id )
            ├── [Phase 3] GeoBlocker::check( $ip )
            ├── DownloadLogger::record( $download_id, $ip, $user_agent )
            ├── UPDATE download_count + 1
            └── DownloadDelivery::serve( $file_path, $filename, $mime_type )
```

// Registered in DownloadDispatcher::register_rewrite()

## Database Tables

### wp_purecart_downloads — Token Registry

```sql
CREATE TABLE {prefix}purecart_downloads (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    order_id        BIGINT UNSIGNED NOT NULL,
    order_item_id   BIGINT UNSIGNED NOT NULL,
    user_id         BIGINT UNSIGNED NOT NULL,
    product_id      BIGINT UNSIGNED NOT NULL,
    file_id         VARCHAR(64)  NOT NULL,    -- WooCommerce downloadable file ID (MD5 key)
    license_id      BIGINT UNSIGNED NULL,     -- FK to wp_purecart_licenses if license-gated
    token           VARCHAR(128) NOT NULL UNIQUE,
    download_count  INT UNSIGNED  NOT NULL DEFAULT 0,
    max_downloads   INT UNSIGNED  NOT NULL DEFAULT 0,   -- 0 = unlimited
    expires_at      DATETIME     NULL,                   -- NULL = never expires
    ip_address      VARCHAR(45)  NULL,                   -- IP at token creation
    created_at      DATETIME     NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY  uniq_token       (token),
    KEY         idx_user_id      (user_id),
    KEY         idx_order_id     (order_id),
    KEY         idx_product_id   (product_id),
    KEY         idx_license_id   (license_id),
    KEY         idx_expires_at   (expires_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### wp_purecart_download_logs — Per-Event Audit Log

```sql
CREATE TABLE {prefix}purecart_download_logs (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    download_id     BIGINT UNSIGNED NOT NULL,
    ip_address      VARCHAR(45)  NULL,
    user_agent      TEXT         NULL,
    country_code    VARCHAR(2)   NULL,
    status          ENUM('success','rejected_expired','rejected_exhausted','rejected_license','rejected_geo') NOT NULL DEFAULT 'success',
    downloaded_at   DATETIME     NOT NULL,
    PRIMARY KEY (id),
    KEY idx_download_id   (download_id),
    KEY idx_downloaded_at (downloaded_at),
    KEY idx_ip            (ip_address),
    KEY idx_status        (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

The `status` column records both successful and failed attempts — essential for fraud detection (e.g., many `rejected_license` events from one IP).

## Token Security Properties

| Property | Implementation |
|---|---|
| Token format | 64 hex chars — `bin2hex( random_bytes( 32 ) )` |
| Uniqueness | `UNIQUE` DB constraint; re-generates on collision (extremely unlikely with 256-bit entropy) |
| Expiry | `expires_at` stored in DB; checked server-side on every request; `NULL` = never expires |
| Count limit | `download_count < max_downloads` enforced server-side; `max_downloads = 0` = unlimited |
| File path exposure | Never — `file_id` resolves to path server-side from WC downloadable files or product meta |
| License gate | When Licensing module active and `_purecart_download_license_gate` is `true`, checks `wp_purecart_licenses.status = 'active'` before serving |
| Token reuse | Multiple downloads allowed up to `max_downloads` limit. Each use logged. |

## License Gate Integration

When both the Licensing and Secure Downloads modules are active, PureCart can require a valid active license before serving a file — even if the download token itself is valid.

This prevents a scenario where a customer: buys a product → gets a token → gets their license revoked → continues downloading with the old token.

```php
// In TokenManager::validate()
if ( $token_row->license_id && get_post_meta( $token_row->product_id, '_purecart_download_license_gate', true ) ) {
    $license = LicenseValidator::get_by_id( $token_row->license_id );
    if ( ! $license || $license->status !== 'active' ) {
        DownloadLogger::record( $token_row->id, $ip, $ua, 'rejected_license' );
        wp_die( __( 'Your license is no longer active.', 'purecart' ), 403 );
    }
}
```

`_purecart_download_license_gate` (bool, default `true` when Licensing module active, `false` when not).

## Delivery Methods

`DownloadDelivery` supports five methods (global default, overridable per product):

| Method | Config | How It Works | Best For |
|---|---|---|---|
| PHP Streaming | `streaming` | `ob_end_clean()` + chunked `fread()` loop | Universal default — works on any host |
| X-Sendfile | `xsendfile` | `X-Sendfile: /abs/path` header (Apache mod_xsendfile) | Apache servers — zero PHP memory usage |
| X-Accel-Redirect | `xaccel` | `X-Accel-Redirect: /protected/path` header (nginx) | nginx servers — zero PHP memory usage |
| S3 Presigned URL | `s3` | `302` to 60-second AWS S3 presigned URL | Files stored in S3 |
| Cloudflare R2 | `r2` | `302` to 60-second Cloudflare R2 presigned URL | Files stored in R2 (no egress fees) |

```php
// DownloadDelivery::serve( $file_id, $filename )
$method = get_post_meta( $product_id, '_purecart_download_delivery', true )
       ?: get_option( 'purecart_download_delivery', 'streaming' );

switch ( $method ) {
    case 'xsendfile':
        header( 'Content-Type: application/octet-stream' );
        header( 'Content-Disposition: attachment; filename="' . $filename . '"' );
        header( 'X-Sendfile: ' . $local_path );
        exit;

    case 'xaccel':
        header( 'Content-Type: application/octet-stream' );
        header( 'Content-Disposition: attachment; filename="' . $filename . '"' );
        header( 'X-Accel-Redirect: ' . $nginx_internal_path );
        exit;

    case 's3':
        wp_redirect( $this->s3_presign( $s3_key, 60 ) );
        exit;

    case 'r2':
        wp_redirect( $this->r2_presign( $r2_key, 60 ) );
        exit;

    default: // 'streaming'
        $this->stream_file( $local_path, $filename, $mime_type );
}
```

### PHP Streaming Implementation

```php
private function stream_file( string $path, string $filename, string $mime ): void {
    if ( ob_get_level() ) {
        ob_end_clean();
    }
    header( 'Content-Description: File Transfer' );
    header( 'Content-Type: ' . $mime );
    header( 'Content-Disposition: attachment; filename="' . rawurlencode( $filename ) . '"' );
    header( 'Content-Transfer-Encoding: binary' );
    header( 'Content-Length: ' . filesize( $path ) );
    header( 'Cache-Control: must-revalidate, post-check=0, pre-check=0' );
    header( 'Pragma: public' );
    header( 'Expires: 0' );
    flush();

    $handle = fopen( $path, 'rb' );
    while ( ! feof( $handle ) ) {
        echo fread( $handle, 1024 * 1024 ); // 1MB chunks
        flush();
    }
    fclose( $handle );
    exit;
}
```

Chunked streaming prevents PHP memory exhaustion on large files (video, full software packages).

## Cloud Storage (Phase 2)

`FileStorageManager` provides an abstraction layer over local filesystem and cloud storage backends.

```php
interface FileStorageBackend {
    public function put( string $tmp_path, string $key ): string;  // Returns storage key
    public function get_url( string $key, int $ttl_seconds ): string; // Presigned URL
    public function delete( string $key ): void;
    public function exists( string $key ): bool;
}
```

Implementations:
- `LocalStorageBackend` — files in `wp-content/uploads/purecart-protected/`
- `S3StorageBackend` — `league/flysystem-aws-s3-v3` adapter
- `R2StorageBackend` — `league/flysystem-aws-s3-v3` adapter with Cloudflare R2 endpoint

Files uploaded via the admin UI are stored in the configured backend. The `file_id` in `wp_purecart_downloads` references the storage key, not a raw path.

**Protected Local Directory:**
Files stored locally go into `wp-content/uploads/purecart-protected/` (configurable). An `.htaccess` rule (Apache) or nginx config snippet (admin provides) blocks direct browser access to this directory.

```apache
# wp-content/uploads/purecart-protected/.htaccess (Apache)
Order Deny,Allow
Deny from all
```

```nginx
# nginx location block (paste into server config)
location ~* /wp-content/uploads/purecart-protected/ {
    deny all;
    return 403;
}
```

## WooCommerce Integration

```php
// Replace WC native download URL with PureCart secure URL
add_filter(
    'woocommerce_downloadable_file_download_url',
    [ DownloadDispatcher::class, 'secure_download_url' ],
    10, 2
);

// Generate tokens when order status changes to completed (or processing, if configured)
add_action(
    'woocommerce_order_status_completed',
    [ OrderHandler::class, 'on_order_completed' ]
);

// Also support processing status (configurable)
add_action(
    'woocommerce_order_status_processing',
    [ OrderHandler::class, 'on_order_processing' ]
);

// Revoke/expire tokens when order is refunded or cancelled
add_action( 'woocommerce_order_status_refunded',  [ TokenManager::class, 'expire_for_order' ] );
add_action( 'woocommerce_order_status_cancelled', [ TokenManager::class, 'expire_for_order' ] );
```

`DownloadDispatcher::secure_download_url()` is called by WooCommerce when rendering the My Account downloads table, order confirmation emails, and "Downloads" button on the order detail page. The replacement is invisible to WooCommerce — it sees a normal URL, but PureCart has replaced it with a secure token URL.

## Multiple Files Per Product

WooCommerce supports multiple downloadable files per product. PureCart creates a separate token for each file in the order item, keyed by the WooCommerce `file_id` (MD5 key string).

```
Order item (qty 1, product: "Pro Plugin Bundle")
    ├── File: my-plugin-1.3.0.zip  → token: a1b2c3...
    ├── File: plugin-docs.pdf      → token: d4e5f6...
    └── File: sample-data.zip      → token: g7h8i9...
```

Each token has its own count limit and expiry. The My Account downloads tab shows each file separately with its own "Download" button.

## Download Link in Order Emails

PureCart replaces the download URLs in WooCommerce's order emails (`customer-processing-order`, `customer-completed-order`) via the same `woocommerce_downloadable_file_download_url` filter. The email contains secure token URLs, not direct file paths.

Token expiry for email links defaults to 7 days (separate from the per-order expiry setting) — enough time to receive and click the email. Configurable via `_purecart_email_link_expiry_days`.

## Developer Hooks

```php
// Filter expiry seconds before token creation (0 = no expiry)
apply_filters( 'purecart_download_expiry_seconds', $seconds, $order_id, $product_id );

// Filter max downloads before token creation (0 = unlimited)
apply_filters( 'purecart_download_max_count', $count, $order_id, $product_id );

// Fired after token is created
do_action( 'purecart_download_token_created', $token_id, $order_id, $product_id );

// Filter: return true to bypass token validation (e.g., for admin users)
apply_filters( 'purecart_download_bypass_validation', false, $token, $user_id );

// Filter: return true to bypass geo-block for specific IP (Phase 3)
apply_filters( 'purecart_geo_block_bypass', false, $ip, $country_code, $token_id );

// Fired when file is successfully delivered
do_action( 'purecart_file_downloaded', $token_id, $ip, $user_agent );

// Fired when download is rejected
do_action( 'purecart_download_rejected', $token_id, $reason, $ip );
// $reason: 'expired' | 'exhausted' | 'license_inactive' | 'geo_blocked' | 'invalid'

// Filter the MIME type used for Content-Type header
apply_filters( 'purecart_download_mime_type', $mime, $file_path, $product_id );

// Filter: allow regenerating an expired token for a specific user
apply_filters( 'purecart_allow_token_regen', false, $token_id, $user_id );

// Fired after tokens are expired by order refund/cancellation
do_action( 'purecart_order_tokens_expired', $order_id );
```

## Video Play-Protect (Phase 2)

For video files (`.mp4`, `.webm`, `.mov`), `VideoProtector` serves the video via an in-page JS player instead of triggering a browser download. The player source URL is a separate, short-lived stream token — not the download token itself.

```
Customer clicks "Watch" → JS player overlay opens
    │
    └── JS: GET /wp-json/purecart/v1/video-stream-token/{download_token}
            ├── Validates download token (same rules as file download)
            ├── Issues a new stream token: 10-minute TTL, single-use
            └── Returns { stream_url: "/purecart-stream/{stream_token}" }

JS player (Video.js or HTML5 native) loads stream_url
/purecart-stream/{stream_token} → VideoProtector::stream()
    ├── Validates stream_token
    ├── Supports HTTP Range requests (byte-range header) for player scrubbing
    ├── Reads and streams in 1MB chunks
    └── Sets stream token as used (prevents URL sharing)
```

Per-product toggle: `_purecart_video_protect` (bool, default `false`). When off, video files download normally.

## Media Library Guard (Phase 2)

`MediaLibraryGuard` prevents direct browser access to files stored in the protected uploads subdirectory.

**Scope:** Only files in `wp-content/uploads/purecart-protected/` are blocked. All other media files remain publicly accessible.

**Implementation (three options, admin chooses):**
1. `.htaccess` rule (Apache) — `Deny from all` injected into `purecart-protected/.htaccess`
2. Nginx config snippet — displayed in admin settings for manual paste into server config
3. PHP `template_redirect` intercept — slowest but requires no server config changes

Files for protected products should be uploaded via the PureCart admin file manager — not via WP Media Library — to ensure they land in the protected directory.

## Geo-Blocking (Phase 3)

`GeoBlocker` runs on every download attempt before the file is served.

**Detection: ip-api.com (free tier)**
```php
$response = wp_remote_get( "http://ip-api.com/json/{$ip}?fields=countryCode" );
$data     = json_decode( wp_remote_retrieve_body( $response ) );
$country  = $data->countryCode ?? '';
// Cached in WP transient for 24 hours per IP — avoids repeated API calls
set_transient( 'purecart_geo_' . md5( $ip ), $country, DAY_IN_SECONDS );
```

**Detection: MaxMind GeoLite2 (local DB, no API call)**
```php
$reader  = new \MaxMind\Db\Reader( WP_CONTENT_DIR . '/uploads/GeoLite2-Country.mmdb' );
$record  = $reader->get( $ip );
$country = $record['country']['iso_code'] ?? '';
```

Result cached in WP transient for 24 hours. DB re-downloaded weekly via Action Scheduler.

Blocked downloads log with `status = 'rejected_geo'` in `wp_purecart_download_logs`.

## Ad Blocker Detection (Phase 2)

When a customer is on the My Account downloads page and an ad blocker is active, a non-intrusive notice explains that the ad blocker may interfere with download initiation tracking.

**Detection method:** A small JS probe loads a fake `ads.js` resource. Ad blockers block resources whose path contains `ads`, `banner`, `popup`, or similar patterns. If the probe fails to load, the notice is shown.

```javascript
// assets/js/purecart-adblock-detect.js
const probe = document.createElement( 'script' );
probe.src   = purecartDownloads.adProbeUrl; // /assets/js/ads.js
probe.onerror = () => {
    document.querySelector( '.purecart-adblock-notice' )
            ?.classList.remove( 'purecart-hidden' );
};
document.head.appendChild( probe );
```

Notice text (translatable): "We detected an ad blocker. If your download doesn't start, please disable it for this site and try again."

## Key Design Decisions

**1. Token is a random 64-char hex, not a signed JWT.** Download tokens live in the DB and are validated server-side. This allows instant revocation (expire a token by updating `expires_at` in the DB) without waiting for a JWT TTL to drain. The Update Manager uses signed tokens for a different reason (no DB lookup required at download time) — but for customer downloads, revocability on refund/cancel is more important than avoiding a DB read.

**2. `max_downloads = 0` means unlimited.** Using zero as the unlimited sentinel avoids a nullable integer and simplifies the DB schema. The display layer converts 0 to "∞".

**3. Separate stream token for video.** The download token is not the stream URL. Issuing a separate 10-minute, single-use stream token prevents the video URL from being shared from browser devtools. The download token itself still tracks the overall download count.

**4. Delivery method is per-product, not just global.** Large video files benefit from X-Sendfile. Small ebooks are fine with PHP streaming. A store may have both. Per-product override makes this practical.

**5. `status` column in download logs records rejections too.** Knowing that a token was attempted but rejected (expired, exhausted, license inactive, geo-blocked) is as valuable as knowing it succeeded. Aggregate rejection data surfaces fraud patterns.

**6. WooCommerce integration via filter, not override.** PureCart hooks `woocommerce_downloadable_file_download_url` — a standard WC filter — rather than replacing WC's download handler. This means PureCart is additive, not destructive: disabling PureCart restores WC's native download links without data loss.

**7. Cloud storage is a Phase 2 feature, not Phase 1.** Most stores start with local file hosting. Introducing S3/R2 abstraction in Phase 1 would add Composer dependencies before the module is proven. Phase 2 adds cloud backends behind the `FileStorageBackend` interface without changing any consuming code.

**8. Geo-blocking uses transient caching.** IP-to-country lookups are cached in WP transients for 24 hours. This avoids hammering ip-api.com (45 req/min rate limit) on stores with high download volume. MaxMind GeoLite2 is the recommended upgrade for high-traffic stores — local DB, no rate limit, no external call.

## Phase Roadmap

**Phase 1 — Core (MVP)**
- `TokenManager`, `DownloadDispatcher`, `DownloadLogger`, `DownloadDelivery`
- HMAC-signed 64-char hex tokens
- PHP streaming delivery
- Per-order, per-file download count limit
- Configurable token expiry (global + per-product)
- License gate (when Licensing module active)
- WooCommerce integration via filters
- Multiple files per product
- My Account downloads tab
- Download log (admin)
- Token revocation on order refund/cancel (Action Scheduler)
- All developer hooks

**Phase 2 — Storage + Media**
- `FileStorageManager`, `S3StorageBackend`, `R2StorageBackend`
- X-Sendfile / X-Accel-Redirect delivery
- S3 and Cloudflare R2 presigned URL redirect
- `VideoProtector` — JS player + stream token + HTTP Range support
- `MediaLibraryGuard` — protected uploads directory + `.htaccess` / nginx rule
- Ad blocker detection notice
- "Get New Link" (customer-side link regeneration, admin-controlled)

**Phase 3 — Geo + DRM**
- `GeoBlocker` — ip-api.com + MaxMind GeoLite2
- CloudFront signed URL delivery (CDN offload with signed cookies / URL)
- DRM watermarking for PDF ebooks (embed customer email/order ID in PDF metadata)
- IP binding option (lock token to the IP that first used it)
- Download throttling (max N downloads per hour per IP)
- WP-CLI commands (`wp purecart download list`, `wp purecart download revoke`)
